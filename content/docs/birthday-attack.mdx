# Understanding Birthday Attacks

## What is a Birthday Attack?

A **birthday attack** is a cryptographic technique used to find **hash collisions**, where two different inputs produce the same hash output.

Unlike a **preimage attack**, which attempts to find an input that matches a specific target hash, a birthday attack searches for **any two inputs** that generate identical hash values. The attack exploits the mathematics of the **Birthday Paradox**, making collisions much more likely than intuition suggests.

---

## The Birthday Paradox

The Birthday Paradox asks:

> *How many randomly selected people are required before there is a 50% chance that at least two share the same birthday?*

Although there are **365 possible birthdays**, the answer is only **23 people**.

This occurs because we are interested in **any matching pair**, not a match with one specific person.

The number of possible pairs among **k** people is

$$
\text{Pairs} = \frac{k(k-1)}{2}
$$

For **23 people**,

$$
\frac{23 \times 22}{2} = 253
$$

possible pairs exist, making a shared birthday surprisingly likely.

---

## Birthday Attacks in Cryptography

Hash functions behave like assigning random birthdays.

If a hash function produces **N** unique outputs,

$$
N = 2^b
$$

where

- **N** = Total hash values
- **b** = Hash output length (bits)

Generating many random hashes eventually leads to two identical outputs.

This event is called a **collision**.

---

## Collision Probability

If **k** random hashes are generated from a hash space of size **N**, the probability of observing at least one collision is approximately

$$
p(k,N) \approx 1 - e^{-\frac{k(k-1)}{2N}}
$$

For sufficiently large **k**, this is often simplified to

$$
p(k,N) \approx 1 - e^{-\frac{k^2}{2N}}
$$

---

## The 50% Collision Threshold

The number of hashes required to reach approximately a **50% probability** of a collision is

$$
k_{50\%} \approx \sqrt{2N\ln2}
$$

which simplifies to

$$
k_{50\%} \approx 1.177\sqrt{N}
$$

Since

$$
N = 2^b
$$

the equation becomes

$$
k_{50\%} \approx 1.177 \times 2^{b/2}
$$

This demonstrates that collisions can typically be found after generating roughly the **square root** of the total hash space.

---

## Collision Search vs. Preimage Search

| Property | Preimage Attack | Birthday Attack |
|-----------|-----------------|-----------------|
| Objective | Find an input matching a specific hash | Find any two inputs with the same hash |
| Target | Fixed hash | Any collision |
| Expected Complexity | $O(2^b)$ | $O(2^{b/2})$ |
| Example (256-bit hash) | $2^{256}$ operations | $2^{128}$ operations |

---

## Why Hash Functions Need Longer Outputs

Birthday attacks effectively reduce the collision security of a hash function by half.

For example:

- **AES-128** provides approximately **128-bit security** because recovering the key requires about

$$
2^{128}
$$

operations.

However,

- **SHA-256** provides approximately **128-bit collision resistance** because birthday attacks reduce the effective complexity to

$$
2^{128}
$$

operations.

Therefore, modern cryptographic hash functions require much larger output sizes than symmetric encryption keys.

---

## Practical Security Implications

Modern secure hash algorithms such as:

- SHA-256
- SHA-384
- SHA-512

are specifically designed so that birthday attacks remain computationally infeasible.

Legacy algorithms such as **MD5** and **SHA-1** are no longer considered collision resistant because practical collision attacks have already been demonstrated.

---

## Password Hashing is Different

Birthday attacks are generally **not** the primary threat against password databases.

Passwords should instead be protected using modern **Key Derivation Functions (KDFs)** such as:

- Argon2
- scrypt
- PBKDF2

These algorithms intentionally slow password verification, making large-scale offline brute-force attacks significantly more expensive.

---

## Key Takeaways

- Birthday attacks search for **collisions**, not preimages.
- The Birthday Paradox explains why collisions occur much sooner than expected.
- Collision attacks require approximately **2^(b/2)** work instead of **2^b**.
- Modern hash functions use larger output sizes to maintain strong collision resistance.
- MD5 and SHA-1 are no longer considered secure against collision attacks.
- Password storage should rely on modern KDFs such as **Argon2**, **scrypt**, or **PBKDF2** rather than fast general-purpose hash functions.
