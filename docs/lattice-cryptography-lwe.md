# Lattice Cryptography & Learning With Errors (LWE)

Post-Quantum Cryptography (PQC) algorithms, such as ML-KEM (Kyber) and ML-DSA (Dilithium), derive their security primarily from the mathematics of lattices. 

## 1. What is a Lattice?
Geometically, a lattice $\Lambda$ is a periodic, infinite grid of points in $n$-dimensional space. It is generated by taking all integer linear combinations of a set of linearly independent basis vectors $\mathbf{b}_1, \dots, \mathbf{b}_n$:
$$ \Lambda = \left\{ \sum_{i=1}^n x_i \mathbf{b}_i \mid x_i \in \mathbb{Z} \right\} $$

## 2. The Hard Problems
The security of lattice-based cryptography relies on the presumed intractability of two fundamental problems (even for quantum computers):

### Shortest Vector Problem (SVP)
Given a basis for a lattice, find the shortest non-zero vector in the lattice.

### Closest Vector Problem (CVP)
Given a basis for a lattice and an arbitrary target point $\mathbf{t}$ in space (not necessarily in the lattice), find the lattice point closest to $\mathbf{t}$.

If you are given a "good" basis (where the vectors are short and nearly orthogonal), solving SVP and CVP is computationally easy using algorithms like Babai's Nearest Plane. However, if you are given a "bad" basis (where the vectors are very long, skewed, and highly parallel), solving these problems in high dimensions is extremely difficult. 

## 3. Learning With Errors (LWE)
The **Learning With Errors (LWE)** problem, introduced by Oded Regev in 2005, is an algebraic problem that is provably as hard as solving certain worst-case lattice problems (like SVP/CVP).

In LWE, you are given a public matrix $A$ (randomly chosen) and a vector $\mathbf{b}$ computed as:
$$ \mathbf{b} = A\mathbf{s} + \mathbf{e} \pmod q $$

Where:
- $\mathbf{s}$ is a secret vector.
- $\mathbf{e}$ is a small error vector (often sampled from a discrete Gaussian distribution).
- $q$ is a public modulus.

The goal is to recover the secret $\mathbf{s}$ given $(A, \mathbf{b})$. Without the error $\mathbf{e}$, this would be a simple system of linear equations solvable via Gaussian elimination. The addition of the small error $\mathbf{e}$ makes the problem extraordinarily difficult.

**Connection to Lattices:** 
The columns of the matrix $A$ can be thought of as a bad basis for a lattice. The vector $\mathbf{b}$ is a target point in space. The vector $A\mathbf{s}$ is a lattice point. The error $\mathbf{e}$ is the distance from the lattice point to the target. Finding $\mathbf{s}$ is therefore equivalent to solving the **Closest Vector Problem (CVP)** for the target $\mathbf{b}$ on the lattice defined by $A$.

## 4. Ring-LWE & Module-LWE
Standard LWE requires massive matrices for $A$, resulting in public keys that are megabytes in size. To make lattice cryptography practical, variants like **Ring-LWE** and **Module-LWE** were introduced.

### Polynomial Rings
Instead of matrices, Ring-LWE operates on polynomials in a specific ring, usually $\mathbb{Z}_q[X] / (X^n + 1)$.
- **$\mathbb{Z}_q$**: All polynomial coefficients are reduced modulo $q$.
- **$(X^n + 1)$**: The polynomials themselves are reduced modulo $X^n + 1$. 

The polynomial modulo $X^n + 1$ implies that $X^n \equiv -1$. Therefore, any term $c \cdot X^{n+k}$ "wraps around" to become $-c \cdot X^k$. This property, known as **negacyclic convolution**, allows polynomials to remain at degree $< n$ during multiplication while preserving cryptographic hardness.

### Module-LWE
Module-LWE (used in ML-KEM/Kyber) strikes a balance between standard LWE (high security, large keys) and Ring-LWE (compact keys, highly structured). It uses small matrices where the elements are polynomials rather than simple integers. This allows the security level to be easily scaled simply by increasing the matrix dimensions.
